Privacy Policy

Effective date: 19 November 2026

This policy explains how World General Knowledge Quiz handles information when it requests YouTube upload authorization and when you visit this website. It is written to reflect the current implementation in the project's public repository.

1. Application identity and purpose

World General Knowledge Quiz is an independently maintained project that generates general-knowledge quiz scripts, narration and short vertical videos. Its publishing tooling can upload a generated quiz video to YouTube so the content can be viewed by a wider audience. The project is not affiliated with or endorsed by Google or YouTube.

This policy covers this website and the project's YouTube publishing tooling. It does not describe the separate practices of Google, YouTube or GitHub, which act under their own terms and privacy policies.

2. Visitor information on this website

This website is static HTML and CSS. Its implementation contains no accounts, forms, analytics, advertising, tracking pixels or cookie collection, and it does not ask visitors to sign in with Google. Consequently, the project does not receive quiz answers, visitor profiles or other user data from this website.

GitHub Pages serves these files over the internet. Standard technical information exchanged between your browser and GitHub, such as your IP address and browser details, is handled by GitHub under GitHub's privacy statement, not by the quiz project.

3. YouTube authorization and the exact scope requested

The publishing tooling requests exactly one Google OAuth scope:

https://www.googleapis.com/auth/youtube.upload

This permission is needed for one purpose: uploading the generated quiz video to the authorized YouTube channel. The project does not request permission to read Gmail messages, Drive files, contacts, profile details or channel analytics, and it does not request any other Google scope for this workflow.

4. How the authorization is used

A repository owner starts the manual YouTube test-upload workflow. The tooling exchanges the stored refresh token for a short-lived access token, then calls the YouTube Data API videos.insert endpoint using a resumable upload to send the generated MP4. It sets the video title, description, tags, category and privacy status, and checks the channel ID returned in the upload response against the configured channel ID.

The upload is currently limited to a private test video started manually. Public and scheduled uploading is not available in this implementation. Google user data obtained through the upload scope is used only to perform and verify this upload.

5. Where credentials are stored

The OAuth client ID, client secret and refresh token, together with a channel identifier, are stored as encrypted GitHub Actions Secrets for this repository. They are mapped into environment variables only for the specific workflow steps that need them. The presence check reports only whether each credential is configured; it never displays credential values.

Credentials are not stored in repository files, website files, generated scripts or publication history. Short-lived access tokens and resumable upload session URLs are held only in the memory of the running workflow step. Error messages are redacted so that credential values are not written to logs.

During OAuth and API requests, the credentials and access token are transmitted to Google's OAuth token and YouTube API endpoints over HTTPS as required to complete the upload. They are not sent to any other service by this project.

6. Records the project keeps

The project maintains its own operational records in the repository:

  • Question usage history records which question IDs were used in each Part so later videos avoid repeats.
  • YouTube publication history records the Part number, video file name, a SHA-256 hash of the video, the video title, the YouTube video ID, upload status, privacy status, timestamps and redacted error information. It is used to prevent duplicate uploads and to reconcile interrupted uploads.
  • Facebook publication history is a separate record for the project's Facebook publishing feature and is not used by the YouTube uploader.

Workflow runs may also retain generated video files and these history files as GitHub Actions artifacts for a limited period. These records are controlled by the project owner in the GitHub repository; they are not sold or used for advertising. No credential values, access tokens or upload session URLs are written to them.

7. Sharing, advertising and limited use

The project contains no advertising, analytics, profiling or data-broker integrations. Google user data and authorization obtained through the upload scope are not sold, shared with third parties, or used for advertising or retargeting. Data is transferred only to Google to carry out the upload and to GitHub as the hosting and automation provider for this repository. Access to stored credentials is limited to the repository's GitHub Actions workflow configuration, which is controlled by the project owner.

8. Revoking access

You can review and revoke the application's access at any time in your Google Account under Security → Your connections to third-party apps and services. Select World General Knowledge Quiz and remove its access. The project owner can also revoke the OAuth client credentials in the Google Cloud Console.

After revocation, the stored refresh token no longer works and future uploads stop until the owner re-authorizes and updates the credential stored in GitHub Actions Secrets.

10. Changes to this policy

This policy may be updated when the project's data handling changes. The current version is the one published on this page with the effective date above. Material changes should be reflected here before any new use of Google authorization data begins.
